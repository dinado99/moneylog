## 3. 시스템 구조

```
[폰 / PC 브라우저]  머니로그 (Next.js, Vercel)
        │  fetch POST (text/plain, 비밀번호 포함)
        ▼
[Google Apps Script 웹 앱]  Code.gs (사용자 시트에 붙여넣기, "나"로 실행)
        │  SpreadsheetApp
        ▼
[구글 시트: 낼나 올인원 가계부]  ← PC에서도 그대로 사용
```

- **저장소는 구글 시트 하나.** 별도 서버·DB 없음. 앱은 받아 둔 시트 내용을 기기에 캐시해 먼저 보여 주고 뒤에서 새로 받는다.
- **Apps Script 웹 앱**이 유일한 백엔드. `text/plain` POST로 보내 CORS 사전 요청을 피하고, 요청마다 비밀번호(TOKEN)를 확인한다.
- 스크립트를 바꾸면 사용자가 **배포 관리 → 새 버전**으로 다시 배포 (URL 유지). 앱이 스크립트 버전(현재 v5)을 확인해 낡았으면 설정 화면에 안내.

### 시트에서 쓰는 곳 (낼나 수식은 건드리지 않음)

| 위치 | 용도 |
|---|---|
| `가계부 기록` B~I (8~1037행) | 날짜·구분·대분류·소분류·내용·금액·입금계좌·출금계좌 |
| `가계부 설정` 분류표 (B~M) | 수입·지출·자산·부채 대분류/소분류 (읽기만) |
| `가계부 설정` 계좌표 P~V (13~82행) | 계좌 목록·시작금액·메모. **O열(정렬 수식)은 쓰지 않음** |
| `수입·지출 달력` L~N | 카드 결제일 등 정기 일정 (읽기만) |
| `moneylog 규칙` 탭 (앱이 만듦) | 가맹점·분류·계좌 자동 분류 규칙 |

### 기록 식별
시트 한 줄을 정규화한 8칸을 JSON 문자열로 만든 값이 **키**. 앱(`record-key.ts`)과 스크립트(`norm()`)가 반드시 같은 모양을 만들도록 맞춰 두어, 수정·삭제 시 시트에서 같은 줄을 찾는다.

## 4. 기능별 구현 내용

### 4.1 화면
- **내역**: 월별 목록·합계, 입력/수정/삭제, 자산 종류·계좌별 필터(고른 계좌 월말 잔고), 뱅크샐러드 가져오기 버튼
- **달력**: 일별 수입·지출, 시트 정기 일정(주말 당기기/밀기 반영)
- **보고서**: 월·연(회계기준월 반영) 분류별 도넛, 고정/변동, 추이
- **자산**: 대분류별 잔고, 전월말·연초 대비, 순자산 추이, 외화
- **설정**: 시트 연결, 규칙 목록, 스크립트 업데이트 안내
- 디자인: Tailwind v4 토큰, 차트 색은 검증된 시리즈 색 7개 + 기타

### 4.2 잔고 계산 (시트 '잔고 보고서'와 동일)
- 자산 = 시작금액 + 입금 − 출금
- 부채(카드) = 시작금액 + 출금(사용) − 입금(상환)
- 이름이 같은 계좌(일시불·할부)는 합쳐서 표시

### 4.3 음수 금액 (엔빵·환불)
10만 원 쓰고 친구가 5만 원을 보내 주면 **수입 5만 원이 아니라 지출 −5만 원**으로 기록 → 지출 합계가 실제로 쓴 돈이 된다. 입력 화면 `−` 버튼, 목록에 "돌려받음" 표시.

### 4.4 뱅크샐러드 가져오기
- 입력: `.xlsx`(내역·현황 시트 모두), CSV, 표 붙여넣기. 카드사·은행 CSV 헤더도 인식.
- **분류 순서**: ① 내가 만든 규칙 → ② 뱅크샐러드 분류가 시트 분류와 **이름 그대로** 같으면 그대로 → ③ 예전에 같은 가게를 넣은 기록 → ④ 뱅크샐러드 → 낼나 기본 대응표
- **결제수단 → 시트 계좌**: 같은 이름(띄어쓰기 무시) → 내가 만든 규칙 → 비슷한 이름 짐작
- **안 맞으면 빨간색**: 분류·결제수단이 시트 설정과 그대로 맞지 않으면 줄을 빨간색으로 하고 이유 표시 ("분류 '식비 › 한식' 시트에 없음"), "안 맞는 것만 보기"
- **처음 보는 카드**는 카드 이름 그대로 부채(💳 신용카드 › 일시불) 계좌로 자동 추가. 카드사 이름만 같은 다른 카드는 합치지 않음
- 시트에 이미 있는 내역(날짜·구분·금액·내용 같음)은 자동 제외
- 확인 화면에서 고친 분류·계좌는 `moneylog 규칙`에 저장 (짐작한 것은 저장하지 않고 **직접 고른 것만**)

### 4.5 자산·부채 현황으로 계좌표 교체
- 뱅크샐러드 현황(자산·부채 두 묶음)을 읽어 계좌표 P~V를 **이름까지 통째로** 교체
- 예전 계좌와 같은 것이면 기록·규칙 속 계좌 이름도 새 이름으로 변경
- 시작금액 = 현황 금액 − (기준일까지 기록의 영향) → 앱·시트 잔고가 현황 금액과 같아짐
- 계좌는 최대 70개 (시트 계좌표 크기)

### 4.6 잔액 기준일
- 문제: 현황 금액은 **그날까지 쓴 돈이 이미 빠진 금액**이라, 그날 이전 내역을 나중에 넣으면 두 번 빠짐
- 해결: 계좌 메모에 `잔액기준 YYYY-MM-DD`를 남기고, 기준일 이전·당일 기록을 **추가·수정·삭제**할 때마다 그만큼 시작금액을 자동 보정 (가져오기·직접 입력·달력 모두). 같은 파일에 같이 들어 있는 내역도 계산에 포함

### 4.7 외화
- **시트 구조는 그대로**: 금액(G)은 원화, 외화 금액은 내용(F) 뒤에 `점심 (USD 12.5)`로 저장 → 낼나 수식 정상 동작, PC에서 표를 정렬해도 어긋나지 않음
- **입력**: "외화로 썼어요" → 통화·외화 금액·환율(또는 원화). 원화를 고치면 환율이 맞춰짐
- **충전은 이동, 지출은 쓸 때**: 우리은행 → 하나머니 충전은 이동(순자산 변화 없음), 여행 가서 쓴 것은 지출. 외화를 들고 있는 계좌에서 쓰면 **평균 충전 환율**이 기본값
- **계좌별 외화 잔액** = 메모의 시작 외화(`외화 USD 100`) + 기록 변동(충전 +, 지출 −, 환전 −)
- 뱅크샐러드 '화폐'가 원화가 아니면 오늘 환율로 원화를 계산하고 빨간색으로 확인 요청 (이전엔 $12.5가 13원으로 들어가던 버그)
- 환율: 키 없는 무료 API(open.er-api.com, 실패 시 jsDelivr currency-api), 기기에 캐시

## 6. 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| Supabase 없이 구글 시트만 | 동기화 대상이 결국 시트, 무료, 공유가 쉬움 |
| 캡처(OCR) 제외 | 유료 토큰 필요 |
| 시간 기록 기능 보류 | 낼나 표에 칸이 없고 옆 열은 PC 정렬 시 어긋남 → 사용자 요청으로 취소 |
| 외화를 내용 칸에 붙여 저장 | 시트 수식·정렬을 깨지 않는 유일하게 안전한 위치 |
| 짐작 연결을 규칙으로 자동 저장하지 않음 | "네이버페이 머니 → 네이버페이" 같은 몰래 생긴 규칙이 계속 틀린 결과를 만듦 |

## 7. 겪은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 저장 후 탭을 오가면 확인 화면이 남음 | 화면 상태 보존(Activity) | 저장 후 상태 초기화 |
| "삼성카드"가 여러 계좌에 걸림 / 삼성증권과 혼동 | 이름 부분 일치 | 카드 계좌만 후보, 카드사 매칭은 카드끼리만 |
| 새 카드가 부채로 안 생김 | 카드사만 같은 기존 카드에 합쳐짐, 현황 교체로 빠질 계좌에 연결 | 다른 카드는 새 계좌, 바뀐 목록 기준으로 연결 |
| 네이버페이 머니가 네이버페이로 | 예전 짐작이 규칙으로 저장, 규칙이 같은 이름보다 우선 | 같은 이름 우선, 짐작은 저장 안 함 |
| 현황 후 내역을 넣으면 잔고 이중 차감 | 현황에 이미 반영된 지출 | 잔액 기준일 보정 |
| 저장이 갑자기 안 됨 (11/19) | 원인 미확인 (스크립트 재붙여넣기 시 비밀번호 미변경 의심) | 실패 이유를 화면에 그대로 표시하도록 수정, 사용자 확인 대기 |
