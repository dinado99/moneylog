# 모바일 가계부 웹앱 구현 보고서

> 작성일: 2026-11-20 · 개발 기간: 2026-10-23 ~ 2026-11-19

## 1. 개요

기존에 구글 스프레드시트 템플릿으로 관리하던 가계부를 **모바일에서 입력·조회**할 수 있도록 웹앱으로 만든 프로젝트다. 별도 서버나 DB 없이 **구글 시트를 그대로 저장소로 사용**해, 모바일 앱과 PC의 시트가 항상 같은 데이터를 보도록 했다. 또한 금융 통합 서비스에서 내보낸 거래내역·자산 현황 파일을 올리면 시트의 분류 체계에 맞게 자동 분류해 입력한다.

### 목표와 결과

| 목표 | 결과 |
|---|---|
| 모바일에서 바로 쓰는 깔끔한 UI | 모바일 우선 웹앱, 홈 화면 아이콘, 라이트·다크 모드 |
| 기존 스프레드시트 기능을 모바일로, PC와 동기화 | 시트를 유일한 저장소로 쓰는 구조, 시트 수식·서식은 그대로 유지 |
| 외부 거래내역 자동 입력 | 엑셀·CSV·표 붙여넣기 → 시트 분류로 자동 분류, 규칙 수정 가능 |
| 운영 비용 0원 | 유료 API 미사용 (무료 호스팅·무료 환율 정보만 사용) |

## 2. 시스템 구조

```
[모바일 / PC 브라우저]  웹앱 (Next.js, Vercel 배포)
        │  HTTPS POST (요청마다 비밀번호 확인)
        ▼
[Google Apps Script 웹 앱]  시트에 붙여넣어 배포하는 스크립트
        │
        ▼
[구글 스프레드시트]  기존 가계부 템플릿 (PC에서도 그대로 사용)
```

- **저장소**: 구글 스프레드시트 하나. 앱은 마지막으로 받은 데이터를 기기에 캐시해 먼저 보여 주고, 뒤에서 최신 데이터를 다시 받는다.
- **백엔드**: Google Apps Script 웹 앱. 요청을 `text/plain`으로 보내 브라우저의 CORS 사전 요청 없이 호출하고, 요청마다 비밀번호를 확인한다. 스크립트 버전을 앱이 확인해 낡은 경우 업데이트를 안내한다.
- **시트 보호 원칙**: 기록 표와 계좌표의 데이터 칸만 쓰고, 템플릿의 수식·보고서 시트는 건드리지 않는다. 앱 전용 데이터(자동 분류 규칙)는 별도 탭에 둔다.
- **기록 식별**: 시트 한 줄의 값을 정규화해 만든 키로 수정·삭제할 줄을 찾는다. 앱과 스크립트가 같은 규칙으로 키를 만들도록 맞췄다.

### 기술 스택
Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4, SWR, Google Apps Script, Vitest, Playwright

## 3. 주요 기능

### 3.1 화면
- **내역**: 월별 목록·합계, 입력/수정/삭제, 자산 종류·계좌별 필터(선택 계좌의 월말 잔고 표시)
- **달력**: 일별 수입·지출, 시트에 등록된 정기 일정(주말이면 앞당기기/미루기 반영)
- **보고서**: 월·연(회계 기준월 반영) 분류별 비중, 고정/변동 지출, 추이
- **자산**: 계좌 분류별 잔고, 전월말·연초 대비 증감, 순자산 추이, 외화 보유액
- **설정**: 시트 연결, 자동 분류 규칙 관리, 스크립트 업데이트 안내

### 3.2 잔고 계산
시트 템플릿의 잔고 보고서와 같은 방식으로 계산한다.
- 자산 = 시작금액 + 입금 − 출금
- 부채(카드) = 시작금액 + 사용 − 상환

### 3.3 차감(음수) 금액
더치페이·환불로 돌려받은 돈을 수입이 아니라 **지출 차감**으로 기록해, 지출 합계가 실제 부담액이 되도록 했다.

### 3.4 거래내역 가져오기
- **입력 형식**: `.xlsx`, CSV, 표 붙여넣기 (금융 통합 서비스 내보내기, 카드사·은행 CSV 헤더 인식)
- **분류 우선순위**: ① 사용자 규칙 → ② 원본 분류명이 시트 분류와 같으면 그대로 → ③ 같은 가맹점의 과거 기록 → ④ 기본 대응표
- **결제수단 → 계좌 연결**: 같은 이름(공백 무시) → 사용자 규칙 → 유사 이름 추정
- **불일치 표시**: 분류·결제수단이 시트 설정과 정확히 맞지 않으면 해당 줄을 빨간색으로 표시하고 이유를 함께 보여 준다. 사용자가 직접 고른 연결만 규칙으로 저장한다.
- **새 카드 자동 등록**: 시트에 없는 카드는 카드 이름으로 부채 계좌를 자동 생성한다.
- **중복 제외**: 날짜·구분·금액·내용이 같은 기존 기록은 자동으로 뺀다.

### 3.5 자산 현황 동기화
- 외부 자산·부채 현황을 올리면 시트 계좌 목록을 그 기준으로 교체하고, 기존 기록·규칙의 계좌 이름도 함께 바꾼다.
- 시작금액을 역산해 앱·시트의 잔고가 현황 금액과 같아지게 한다.
- **잔액 기준일**: 현황 금액에는 그날까지의 거래가 이미 반영되어 있으므로, 기준일 이전 기록을 나중에 추가·수정·삭제하면 시작금액을 자동 보정해 이중 반영을 막는다.

### 3.6 외화
- 시트 구조를 바꾸지 않기 위해 금액 칸은 원화로 두고, 외화 금액은 내용 뒤에 `(USD 12.5)` 형식으로 함께 저장한다. 템플릿 수식과 PC에서의 표 정렬에 영향이 없다.
- 입력 시 외화 금액·환율·원화 중 둘을 넣으면 나머지를 계산한다.
- 외화 충전은 **이동**, 실제 사용은 **지출**로 기록한다. 계좌별 외화 잔액과 평균 충전 환율을 기록에서 계산하고, 외화 계좌에서 지출할 때 평균 충전 환율을 기본값으로 쓴다.
- 환율은 키가 필요 없는 무료 API를 쓰고, 실패하면 대체 출처를 사용한다.

## 4. 품질 검증

- **단위 테스트 34개** (Vitest): 잔고 계산, 차감 금액, 자동 분류, 계좌 연결, 계좌표 교체, 잔액 기준일 보정, 외화, 필터
- **E2E 테스트** (Playwright, 모바일 화면): 실제 시트 템플릿을 옮긴 모의 스프레드시트 위에서 배포용 Apps Script를 그대로 실행해, 입력부터 시트에 저장된 결과까지 확인
- 변경마다 타입 검사·린트·프로덕션 빌드 수행
- 프레임워크 보안 권고에 따라 Next.js를 패치 버전(16.4.6)으로 업데이트. 배포 의존성의 알려진 취약점은 0건이다.

## 5. 주요 설계 결정

| 결정 | 이유 |
|---|---|
| 별도 DB 없이 스프레드시트만 저장소로 사용 | 동기화 대상이 결국 시트, 비용 없음, 시트 공유만으로 여러 명 사용 가능 |
| 이미지 인식(OCR) 입력 제외 | 유료 API가 필요해 비용 목표에 맞지 않음 |
| 시트 템플릿 구조 변경 없음 | 기존 수식·보고서와 PC 사용 방식을 그대로 유지 |
| 추정 연결은 규칙으로 자동 저장하지 않음 | 잘못된 추정이 규칙이 되어 오류가 반복되는 문제를 방지 |

## 6. 개발 중 해결한 주요 이슈

| 이슈 | 원인 | 해결 |
|---|---|---|
| 서로 다른 카드가 하나의 계좌로 합쳐짐 | 카드사 이름만으로 연결 | 카드사만 같으면 별도 계좌로 생성, 추정 연결은 확인 화면에 표시 |
| 결제수단이 비슷한 다른 계좌로 연결됨 | 과거 추정 결과가 규칙으로 저장되어 같은 이름 계좌보다 우선 적용 | 같은 이름 계좌 우선, 추정 결과는 저장하지 않음 |
| 자산 현황 반영 후 잔고 이중 차감 | 현황 금액에 이미 반영된 거래를 다시 반영 | 잔액 기준일 기반 시작금액 자동 보정 |
| 외화 거래가 원화로 잘못 입력됨 | 통화 칸을 읽지 않음 | 통화를 인식해 환율로 원화 계산, 확인 화면에서 검토 |
| 저장 실패 원인을 알 수 없음 | 오류 메시지를 일반 문구로 덮어씀 | 시트가 보낸 실패 이유를 그대로 표시 |

## 7. 향후 과제

- 실제 운영 환경(스프레드시트·환율 API)에서 장기 사용 검증
- 정기 일정(결제일 등)을 앱에서 직접 편집
- 카드대금 이체 시 대상 카드 자동 연결 보완
